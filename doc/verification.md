2026-10-05，MiniMax Code 桌面版先以 3.1.0 完成首次使用者验收，更新到 **3.1.1（构建 3.1.1.179）**后，在新会话核验原生 skill 与 MCP。使用模型 MiniMax-M3.1-Flash-Preview。公开仓库克隆基线为 `2999861af6daa0dae6dae9dbe72d8c250c5b603b`；克隆源码保持干净，所有记录和配置放在独立测试工作区。

| 实际动作 | 结果与证据边界 |
| --- | --- |
| 按 README 克隆、安装依赖、生产构建、启动空库 | MiniMax Code 实际执行；Node.js 22.22.3、npm 10.9.8，构建通过，网页只监听回环地址 |
| CLI 保存两条灵感、检索、全量列表、建立连线 | 两条不同 ID，一条无向连线；网页显示两张卡片，CLI 与网页接口读回一致 |

原生 MCP 本轮实际调用五种工具：`read_inspiration`、`list_inspirations`、`list_inspiration_tags`、`search_inspirations`、`update_inspiration`。其余八种只核实注册；其中创建、连线等已通过本轮 CLI 或先前自动检查，不能据此声称它们均已通过 MiniMax Code 原生调用验收。本轮未重新验证附件、超过一页的列表、服务重启或真实服务器。

取证同时核对了客户端原始调用和结果记录，而非只采信模型生成的报告；安装阶段与原生接入阶段分开保留。LingBranch MCP 配置与技能副本位于独立测试工作区。原始日志包含机器路径，保留在本地测试工作区，不进入公开仓库。可复用的配置步骤见 [客户端接入说明](ai-clients.md)。

配置取证有时间边界：原生接入完成后的即时复核，四份已存在全局配置与用户更新后记录的哈希一致；后续独立文档审查及同机其他活动期间，MiniMax Code 与 Z Code 的设置文件哈希发生变化，来源未确定，因此不对整轮“全局配置完全未变”作断言，未回滚用户的现有状态。
