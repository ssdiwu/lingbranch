首轮 Host 检查曾失败：Node fetch 自动归一化 Host，实际没有发送预期恶意值。独立回显实验确认后改用原生 HTTP，仍断言 403，没有降低保护要求。附件故障检查中的 `simulated storage failure` 是主动注入。

## 网页与审查

使用 ego-browser 实际操作生产构建，数据仍在隔离目录。验证了空库新增两条灵感，文本与图片上传，检索附件文字，画布连线，独立 MCP 修改后网页刷新读回，以及如下场景：

| 网页动作 | 实际观察 |
| --- | --- |
| 含图片、长正文、三个标签的卡片 | 300px 宽、实测约 349px 高，两张卡片的可见边界不重叠 |
| 筛选中移动、清除筛选、键盘移动 | 临时位置不写回；键盘持久位置从 120 变为 140 并可读回 |
| 全量列表继续读取 | 第一页 50 条，继续到 55 条，显示已读取全部记录 |
| AI 新增后直接从列表打开 | 详情显示列表刚读到的完整内容，不依赖旧画布缓存 |
| 网页草稿与另一端更新冲突 | 草稿保留，展示最新版本，核对前禁止保存 |
| 拖动与另一端更新冲突 | 位置恢复，错误提示保留 |
| 另一入口把视野保存为 panX=777 后刷新、筛选再清除 | 仍保留 777；主动缩放则成功保存为 zoom=1.2 |
| 下载与图片查看 | 网页下载文件与上传原件逐字节一致；图片加载成功，关闭后焦点回到图片按钮 |
| 窄屏 | 新增、搜索、列表、详情和附件可操作；搜索独占一行，文档宽度与 CSS 视口一致，无横向溢出 |

窄屏使用浏览器模拟，不能替代真机触摸验收。浏览器自动定位在移动模拟下发生过视口缩放与卡片点击超时，改用已存在的键盘入口后完成同一详情及附件路径，未据此宣称真机触摸已通过。
